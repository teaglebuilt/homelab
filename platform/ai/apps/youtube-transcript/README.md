# youtube-transcript

Captions + metadata for a YouTube video, over plain HTTP.

| Route | Returns |
|---|---|
| `GET /healthz` | liveness, configured languages |
| `GET /transcript?video_id=<id>` (or `?url=`) | `{video_id, available, url, segments:[{text,start,duration}], captions_source, title, uploader, upload_date, duration}` |
| `GET /video_info?video_id=<id>` | metadata only |
| `GET /markdown?video_id=<id>` | `{video_id, available, path, markdown, segments, …}` — the knowledge note, not stored |
| `POST /ingest?video_id=<id>[&force=true]` (or JSON `{"video_id"\|"url"}`) | renders the note and posts it to `kb-ingest`; returns kb-ingest's `{path, doc_hash, chunks, status}` |

## MCP

The same routes are served as MCP tools at `/mcp` (streamable HTTP), generated
from the FastAPI OpenAPI spec by `FastMCP.from_fastapi`. Tool name =
route `operation_id`: `get_timed_transcript`, `get_video_info`,
`get_transcript_markdown`, `ingest_video`. Add a route with an `operation_id`
and it becomes a tool; `include_in_schema=False` (as on `/healthz`) keeps it
out. kagent reaches it through `platform/ai/kubernetes/mcp/youtube-transcript.yaml`.

## Knowledge note

`/markdown` and `/ingest` build the note in code from every caption segment —
no LLM in the write path, so nothing is dropped or paraphrased. The body puts
segments verbatim under a `## h:mm:ss` heading every
`YT_HEADING_INTERVAL_SECONDS` (each followed by a `&t=` deep link), because the
knowledge chunker splits on headings. Output is deterministic for a given
transcript, so re-posting a video is `status: unchanged` rather than a re-embed.
Notes land at `tree/youtube/<video_id>.md`. A caption-less video returns
`available: false` and posts nothing, so `kb-ingest /exists` stays false and a
poller retries it.

`kb-ingest` runs on **application**; this service runs on **mlops** and reaches
it through the ClusterMesh front door in
`platform/ai/kubernetes/apps/kb-ingest/mesh`. Agents read a whole stored video
back with `kb-retrieval`'s `kb_get_document(path)`.

A caption-less video returns **200** with `{"available": false, "reason":
"no_transcript", "segments": []}` — deliberately *not* 404. Starlette already
uses 404 for an unmatched route, so a 404 here would make a misconfigured URL
indistinguishable from a video that genuinely has no captions, and a caller
would silently "skip" forever. Callers must branch on `available`, and treat any
non-200 as a real error worth surfacing.

There is no ASR fallback by design — callers skip caption-less videos rather
than fabricate a transcript.

| condition | status | body |
|---|---|---|
| captions found | 200 | `available: true`, populated `segments` |
| no captions | 200 | `available: false`, `reason: no_transcript` |
| unparseable video id | 400 | `{"error":"bad_request"}` |
| upstream failure | 502 | `{"error":"upstream_error"}` |
| unmatched route | 404 | `text/plain` — a misconfiguration, never a content signal |
`captions_source` is always `unknown`: youtube-transcript-api's fetch result does
not surface the manual-vs-autogenerated flag, and guessing would be worse than
admitting it.

Metadata (yt-dlp) is best-effort — a metadata failure still returns captions.

## Why not wrap jkawamoto/mcp-youtube-transcript

The architecture plan called for wrapping that package. It is stdio-MCP-only, and
the n8n ingestion workflow needs plain HTTP, which would mean running an MCP
client inside an HTTP server. This service calls the same underlying libraries
(`youtube_transcript_api` for captions, `yt-dlp` for metadata) directly, so the
fetch logic is still not hand-rolled. The MCP facade is generated from these
HTTP routes (see MCP above), so the HTTP contract and the tools cannot drift.

## Proxy

YouTube rate-limits datacenter IPs harder than residential ones. Set either:

- `WEBSHARE_PROXY_USERNAME` + `WEBSHARE_PROXY_PASSWORD`, or
- `YT_HTTP_PROXY` / `YT_HTTPS_PROXY`

Unset, requests egress from the pod IP directly.

## Config

| Env | Default | Meaning |
|---|---|---|
| `YT_LANGUAGES` | `en` | comma-separated caption language preference |
| `YT_METADATA` | `true` | set false to skip the yt-dlp metadata call |
| `YT_HEADING_INTERVAL_SECONDS` | `240` | seconds of video per `##` section (min 30) |
| `KB_INGEST_URL` | `http://kb-ingest.ai.svc.cluster.local:3000` | knowledge write plane |
| `KB_INGEST_TOKEN` | unset | bearer token for kb-ingest (Secret `kb-ingest-token`) |
| `KB_INGEST_PATH_PREFIX` | `tree/youtube/` | must sit inside kb-ingest's `KB_INGEST_PATH_PREFIXES` |
| `KB_INGEST_TIMEOUT_SECONDS` | `300` | long videos embed many chunks |
